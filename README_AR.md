# PLUS90 SHOP — دليل التركيب من الصفر

هذا مشروع متجر عربي لبيع الأحذية والكوتشيات. الواجهة ثابتة على Cloudflare Pages، ووظائف الخادم داخل مجلد `functions/`، والطلبات والكتالوج التشغيلي في Cloudflare D1. يرفع الأدمن صور المنتجات إلى مستودع GitHub ويحدّث ملف `public/data/products.json` كنسخة JSON مقروءة/احتياطية.

> **قبل البدء:** الملفات لا تحتوي على صور شعاراتك نفسها، لأن الصور الأصلية لم تُرفق مع ملف المشروع هنا. انقل ملفات الشعار التي عندك إلى مجلد `public/` بجوار `index.html` وبنفس الأسماء تمامًا.

## 1) الملفات المطلوبة في المستودع

- `public/index.html` — واجهة المتجر.
- `public/admin.html` — لوحة الأدمن. افتحها من `/admin.html`.
- `public/styles.css` و`public/app.js` — شكل المتجر ووظائفه.
- `public/admin.css` و`public/admin.js` — شكل لوحة الإدارة ووظائفها.
- `public/data/products.json` — نسخة JSON من الكتالوج؛ يحدّثها النظام آليًا.
- `public/assets/products/` — مجلد صور المنتجات التي يرفعها الأدمن.
- `functions/` — وظائف الخادم: عرض المنتجات، تسجيل الطلبات، حماية الأدمن، والربط بـ GitHub.
- `schema.sql` — الجداول التي تنشأ في D1.
- `wrangler.toml` — ربط مشروع Pages بقاعدة D1 وإعدادات مستودع GitHub.

### وضع الشعارات

ضع الصور بجوار `public/index.html` كما طلبت:

- `public/P90-LOGO-01.png` — شعار أعلى المتجر، والضغط عليه يرجع للرئيسية.
- `public/P90-LOGO-02.png` — أيقونة التبويب (favicon).
- `public/P90-LOGO-03.png` — الصورة التي تظهر عند مشاركة رابط الموقع. أعددت أيضًا بيانات Open Graph بعنوان **P90 SHOP** ووصف **تسوق لأفضل الأحذية وبأفضل الأسعار**.

لا تغيّر أسماء الصور؛ الأسماء حساسة لحالة الأحرف على الاستضافة.

## 2) أنشئ مستودع GitHub

1. افتح https://github.com/new وسجّل الدخول.
2. أنشئ مستودعًا باسم `plus90-shop`.
3. اجعله **Public**. هذا مطلوب في هذا الإصدار لأن صور المنتجات تُعرض من روابط `raw.githubusercontent.com` العامة. لا تضع في المستودع أي أسرار أو بيانات عملاء.
4. ارفع كل محتويات مجلد `plus90-shop` إلى جذر المستودع. يجب أن يظهر المجلدان `public` و`functions` وملف `wrangler.toml` في المستوى الأعلى، وليس داخل مجلد متداخل آخر.
5. ارفع الشعارات الثلاثة داخل `public/` بجوار `index.html`.

## 3) أنشئ قاعدة بيانات D1

1. افتح https://dash.cloudflare.com/ وسجّل الدخول أو أنشئ حسابًا.
2. من لوحة Cloudflare افتح **Workers & Pages** ثم قسم **D1 SQL Database** (قد يختلف موضعه قليلًا حسب شكل لوحة التحكم).
3. أنشئ قاعدة باسم `plus90-shop`.
4. افتح قاعدة البيانات، ثم افتح **Console**.
5. افتح الملف `schema.sql` من مستودعك، وانسخ محتواه كاملًا إلى Console ثم نفّذه مرة واحدة. ينشئ هذا جداول المنتجات والطلبات.
6. في صفحة تفاصيل قاعدة البيانات انسخ **Database ID**.
7. افتح `wrangler.toml` في GitHub واضغط Edit، واستبدل `PASTE_YOUR_D1_DATABASE_ID_HERE` بمعرّف قاعدة البيانات الحقيقي. لا تضع علامات `< >` حول المعرف. احفظ التعديل على فرع `main`.

## 4) اربط الموقع بـ Cloudflare Pages

1. من Cloudflare افتح **Workers & Pages** ثم اضغط **Create application** وبعدها **Pages** أو خيار الربط بمستودع Git.
2. اختر **Connect to Git** واربط حساب GitHub، ثم اختر مستودع `plus90-shop`.
3. عند إعدادات البناء استخدم:
   - Production branch: `main`
   - Framework preset: `None` (أو `None/Other`)
   - Build command: `exit 0`
   - Build output directory: `public`
4. أكمل الإنشاء وانتظر أول نشر. ستحصل على رابط مثل `https://plus90-shop.pages.dev`.
5. إذا أظهرت Logs أن إعداد D1 غير موجود، تأكد أن ملف `wrangler.toml` في جذر المستودع، وأن `database_id` صحيح، ثم أعد النشر.

**مهم:** اربط إعدادات D1 نفسها في بيئة **Production** الخاصة بمشروع Pages. عند استخدام ملف `wrangler.toml` أعلاه، يفترض أن يستخدم Pages الربط `DB` منه. يمكنك التأكد من **Settings → Functions / Bindings** حسب واجهة لوحة التحكم. اسم الـ binding يجب أن يكون بالضبط `DB`.

## 5) أضف إعدادات الأمان والأسرار

من **Workers & Pages → مشروع plus90-shop → Settings → Variables and Secrets** (اختر بيئة Production)، أضف القيم التالية. القيم الموصوفة بأنها **Secret** يجب إضافتها كـ **Encrypt/Secret**، ولا تكتبها في ملفات GitHub.

### أسرار (Secrets)

- `GITHUB_TOKEN` — توكن GitHub الذي يسمح للخادم بقراءة وكتابة ملفات المستودع.
- `ADMIN_PASSWORD` — كلمة المرور التي ستكتبها في صفحة الأدمن لتسجيل الدخول.
- `ADMIN_SESSION_SECRET` — قيمة عشوائية طويلة مخصصة لتوقيع جلسة الأدمن. استخدم 32 حرفًا عشوائيًا على الأقل، ولا تجعلها نفس كلمة مرور الأدمن.

بعد إضافة الأسرار، احفظها وأعد نشر Pages إن طلبت لوحة Cloudflare ذلك.

### إنشاء توكن GitHub بأقل صلاحيات

1. افتح https://github.com/settings/personal-access-tokens/new
2. اختر **Fine-grained token**.
3. امنح التوكن وصولًا إلى المستودع `plus90-shop` فقط.
4. تحت **Repository permissions** اجعل **Contents = Read and write**. لا يحتاج هذا المشروع إلى صلاحيات Issues أو Actions أو Administration.
5. أنشئ التوكن وانسخه مباشرة إلى Secret باسم `GITHUB_TOKEN` في Cloudflare.
6. لا تلصق هذا التوكن في `index.html` أو `admin.html` أو أي ملف JavaScript أو في محادثات عامة. لا يمكن عرض التوكن مرة ثانية بعد مغادرة شاشة إنشائه.

### متغيرات GitHub غير السرية

في `wrangler.toml` تأكد من تعديل هذه القيم قبل النشر:

```toml
[vars]
GITHUB_OWNER = "اسم-حسابك-على-GitHub"
GITHUB_REPO = "plus90-shop"
GITHUB_BRANCH = "main"
```

إذا غيّرت اسم المستودع أو الفرع، حدّث القيم لتطابقهما تمامًا. هذه القيم ليست أسرارًا؛ توكن GitHub وحده هو الذي يظل Secret.

## 6) الدخول إلى لوحة الأدمن

بعد نشر الموقع، افتح:

`https://اسم-مشروعك.pages.dev/admin.html`

استبدل `اسم-مشروعك` بالجزء الحقيقي من رابط Pages. أدخل قيمة `ADMIN_PASSWORD` التي حفظتها في Cloudflare. لا يوجد حقل للتوكن في المتصفح عمدًا؛ عمليات GitHub تتم من الخادم باستعمال الـ Secret.

من صفحة الأدمن يمكنك إضافة/تعديل/حذف المنتجات، رفع الصور، وتغيير حالات الطلبات. البحث عن الطلبات يعمل بكود مثل `CL0002` أو باسم العميل أو الهاتف.

## 7) كيف تعمل عملية الطلب؟

1. السلة تحفظ على نفس المتصفح والجهاز باستعمال `localStorage`، فلا يحتاج العميل إلى حساب. لن تنتقل السلة تلقائيًا بين الأجهزة أو المتصفحات.
2. عند إكمال الطلب، يكتب العميل الاسم ورقم الهاتف والبريد الإلكتروني الاختياري.
3. يرسل الموقع إلى الخادم أكواد المنتجات والكميات والمقاسات فقط. يعيد الخادم قراءة الأسعار الحقيقية من D1، ثم يحفظ نسخة من بيانات الطلب وسعر كل منتج وقت الطلب.
4. يولّد الخادم كود طلب متتابعًا مثل `CL0002` ثم يفتح واتساب إلى `+201126090244` برسالة جاهزة بالشكل المطلوب.
5. يظل الطلب محفوظًا في لوحة الأدمن حتى لو لم يرسل العميل رسالة واتساب. تأكيد الطلب لا يحذف السجل. السلة المحلية تُفرغ بعد نجاح حفظ الطلب في الخادم.

**تنبيه:** رابط واتساب برسالة جاهزة لا يرسل الرسالة تلقائيًا؛ العميل يحتاج أن يضغط إرسال داخل واتساب. تسجيل الطلب في قاعدة البيانات يتم قبل فتح واتساب.

## 8) رابط المشاركة في واتساب وفيسبوك (OG)

بعد أول نشر، افتح `public/index.html` وعدّل قيمة `og:image` لتطابق نطاق Pages الحقيقي، مثل:

```html
<meta property="og:image" content="https://plus90-shop.pages.dev/P90-LOGO-03.png">
```

استبدل المثال برابطك الحقيقي إن كان مختلفًا. عند ربط دومين خاص لاحقًا، حدّث الرابط إلى الدومين الجديد. معاينات منصات التواصل قد تحتفظ بنسخة مخبأة لبعض الوقت.

## 9) اختبر المتجر قبل مشاركته

- سجّل الدخول إلى `/admin.html` وتأكد أن الدخول بكلمة المرور يعمل.
- أضف منتجًا تجريبيًا بصورة JPG أو WebP وسعر وكود.
- تأكد من ظهوره في صفحة المتجر، وابحث عنه بالاسم والكود.
- أضفه للسلة، أعد تحميل الصفحة، وتأكد أن السلة ما زالت موجودة.
- أنشئ طلبًا تجريبيًا ببياناتك، وتأكد من ظهور كود مثل `CL0001` في رسالة واتساب وفي لوحة الأدمن.
- غيّر حالة الطلب من لوحة الأدمن، ثم جرّب الخروج. تأكد أن `/api/admin/orders` لا يعرض الطلبات من دون جلسة أدمن.
- جرّب تعديل المنتج واحذف منتجًا تجريبيًا.

## 10) ملاحظات وحدود مهمة

- **مصدر بيانات المتجر الفعلي هو D1.** ملف `public/data/products.json` نسخة متزامنة مع GitHub لتكون مقروءة ويمكن الاحتفاظ بها أو مراجعتها. هذا التصميم يجعل تحديث المتجر فوريًا بدل انتظار إعادة بناء Pages بعد كل تعديل.
- إذا فشل توكن GitHub أو إعداد المستودع، قد يحفظ الخادم تغيير المنتج في D1 لكنه يعرض تحذيرًا بأن نسخة JSON لم تُحدَّث. راجع إعدادات GitHub ثم اضغط حفظ مرة أخرى بعد التأكد من البيانات.
- صور المنتجات المرفوعة تبقى في GitHub حتى بعد حذف المنتج من اللوحة؛ لا يحذف المشروع الصور القديمة تلقائيًا حتى لا يمسح صورة مشتركة بين منتجات.
- لا تضع أي بيانات حساسة للعملاء في `products.json`. معلومات العملاء محفوظة في D1 ولا تُعرض إلا من خلال مسارات API المحمية بجلسة الأدمن.
- هذا المشروع لا يرسل رسالة واتساب تلقائيًا، ولا يعالج الدفع الإلكتروني أو الشحن أو المخزون. تأكيد الطلب وإتمام البيع يتمان يدويًا مع العميل.
- الخدمات المجانية مناسبة للبدء ضمن حدود استخدام كل خدمة، لكنها ليست ضمانًا بأن التشغيل سيبقى مجانيًا مع أي حجم للزيارات أو الملفات.
